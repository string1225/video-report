# 内容与制作 SOP

## 材料 → 结论 → 分镜

复用当前对话已有研究，保存新增来源的题名、作者、年份、原始链接、核对范围及对应论点。找不到全文时，可以使用可靠原始摘要明确支持的结果；不能补填未核实的样本、效应量和分组。

先写一句中心结论，选三至五个支撑点。研究的偏好、观看参与、理解、记忆、操作和商业转化是不同指标。人口与情境、比较组、资源投入不同的研究，不能强拼成统一排名。

每页分镜列出：结论标题、主视觉、画面文字、完整口播、来源ID、素材ID与动画时点。调研时同时摘取相关图片、原文图表和短视频，记录来源、作者、许可与改动；具体方法见 [素材与动画](media-and-motion.md)。示意片段标明用途，不能当作原研究现场。建议顺序是问题与结论、关键证据、解释与边界、可执行建议。说明不确定性应紧邻相关结果，不只放在最后一页。

## 报告 → 口播

- 口语化短句，明确数字的单位、基准和含义。口播避免长串URL和文献书目，完整来源放交付文件。
- 屏幕标题表达结论，图表表达关系，旁白解释为什么。不要逐行朗读密集报告。
- 缩写、年份、小数、单位先试音。展示文本和读音不一致时，使用 `narration_segments` 的 `text` / `spoken`，由实测分段音频绑定字幕。
- 先用自然速度合成；超时优先删枝节、改文案，避免不断加速。
- 用户反馈冗长时，先删除重复结论、过多数字和反复的方法解释，把必要限制紧邻证据保留一次；同步精简屏幕文字。用户明确指定相对语速倍率时，再按该倍率处理音频与字幕，不将百分比加点误当成相对倍速。

## 分阶段制作

1. 验证来源和输入数据：`validate`。
2. 用少量场景做短样片 `build`；确认字体、密度、音色与输出链路。已有明确风格时自行验证后继续，不引入额外批准步骤。
3. 全片 `build`。检查实际时长，不用预估字数冒充测量。
4. 检查 `contact-sheet.png` 每页，并检查同页不同时刻的带字幕成片帧；确认进度变化、要点显现、视频实际运动与素材切换。测试HTML上一页、下一页、播放、拖动和回退。
5. `check` 完整解码与校验音轨、帧数、尺寸和字幕区间。抽听旁白、交界和数字；无法听取时如实记录。
6. 保留 `qa.json` 和 `manifest.json`。用户后续改配音、颜色或字幕，可恢复制作。

## 交付

`video.mp4`、`deck/`（HTML、样式、运行脚本、media和MEDIA-CREDITS.md）、`voice.wav`、字幕、`report.json`、分镜、研究来源、`media-sources.json`、统一时间轴、制作记录、QA、封面及联系表。成片涉及分享许可时同时交付署名/许可说明。

生成目录还包含缓存与阶段记录，便于恢复。日常交付链接指向关键产物，不必要求观众理解实现细节。需要独立移动交付目录时，保持 HTML 的相对文件结构完整。

## 按需继续发布

用户要求上传或发布时，完成成片 QA 后按 [发布与成片交接](publishing.md) 使用本次精确 `video.mp4`，复用已经确认的标题和封面意图。将发布内容包与制作 `report.json` 分开保存。没有发布要求就交付制作产物；发布依赖缺失时保留制作成果并报告缺项，不重做视频。
