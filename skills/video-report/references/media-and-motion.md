# 素材摘取与确定性动画

## 调研时一并收集可用画面

为每个关键论点寻找能帮助解释的原文图表、产品截图、操作照片或3～8秒动作片段。优先原始来源和明确允许复用的素材；不要只存文章链接，实际摘取并保存到任务的`assets/`。没有相关、可用的画面时保留图表或文字，不塞无关风景。

检索网站和提取媒体可按当前浏览器skill进行；制作任务不检查发布账号。在线来源、原始下载和最终剪裁文件分别记录。论文摘要或网页公开可读不代表图片可自由复用，核对具体图片/视频的作者及许可。用户自有素材也登记提供方与用途。

图片保留表达论点所需的区域；原文图表保留单位、图例、分组及必要脚注，不改动数字。片段保留动作完整性，以FFmpeg精确裁剪并去掉原音，避免与旁白混杂。示意照片/片段在画面中标注，不能冒充研究或事件现场。

不需要新增Python依赖。图片裁剪用已有Pillow；视频用现有FFmpeg。HTML优先使用VP9/WebM，避免浏览器缺少H.264解码器。示例（路径按任务调整）：

```powershell
.tools/bin/ffmpeg.exe -hide_banner -y -ss 13 -i original.ogv -t 6 -an -vf "scale=trunc(iw*sar/2)*2:ih,setsar=1,fps=30" -c:v libvpx-vp9 -crf 34 -b:v 0 assets/steps.webm
```

论文页面可用当前PDF工具渲染后裁剪，渲染器属于可选调研工具，不是视频构建必需项。素材尺寸、时长、显示比例、解码和实际内容都要检查；缩略图不是视频片段。

## 输入与打包

顶层`media`登记素材；`path`相对于`report.json`。每个素材需`id/type/path/title/source_url/creator/license/attribution`；建议同时保存`license_url/download_url/changes/sha256`，`credit`为画面短署名。文件校验通过后复制到`deck/media/`，使用内容哈希文件名和相对路径；不会把远端链接当作已下载素材。

```json
{
  "motion": {"enabled": true},
  "media": [{
    "id": "M1", "type": "video", "path": "assets/steps.webm",
    "title": "动作步骤节选", "source_url": "原始说明页URL",
    "creator": "原作者", "license": "具体许可及版本",
    "license_url": "许可URL", "attribution": "完整署名与改动",
    "credit": "作者 · 许可 · 节选/静音"
  }]
}
```

在普通内容页设置`"media":{"id":"M1","caption":"步骤示意，非研究现场","fit":"contain"}`，采用左文右图。`contain`保留全图，`cover`允许裁切并轻缓推近，原文图表使用`contain`。视频默认从本次出现时起播放，片尾停住；`loop:true`可循环。

同页可用`scene.media.switches`切换素材，例如：

```json
{"id":"clip","caption":"动作示意，非研究现场","switches":[
  {"id":"paper-table","cue":1,"offset_ms":4000,"caption":"原文表2","fit":"contain"}
]}
```

这里`cue:1`指本页第2条整句字幕的起点，再加4000ms。它只是画面编排时间，不声称精确对应句中某个词。切入视频从切换点计时，回退会恢复原素材。

构建输出`media-sources.json`与`deck/MEDIA-CREDITS.md`；将素材作者、原始链接、许可和改动随交付保留。第三方素材不受代码MIT许可覆盖。BY-SA等许可还可能约束组合成片的许可，按实际素材确定`output_license`；本案例成片组合采用CC BY-SA 4.0，外部资产各自保留原许可。

## 画面跟随讲解

默认新建报告启用`motion.enabled:true`。模板支持标题淡入、卡片/选择行依次出现、条形图增长、整体进度推进和照片轻缓推近。动效只服务于当前讲解，来源、字幕及研究限制保持可读。

`scene.reveal_cues:[0,1]`把本页第1、2个要点绑定到第1、2条整句字幕起点。省略时按页面时长错开显现。索引超出本页字幕数会报错。旁白变化后重建音频与字幕，画面自动使用新的时间；不修改字幕来凑动画。

HTML播放器由旁白时钟驱动；导出调用`renderFrame(frame_index*1000/fps)`，等待字体、图片及视频定位解码，再把每一帧直接送入FFmpeg。最终字幕仍只烧录一次，配音与总帧数仍使用实际PCM样本时间轴。CSS实时动画、浏览器录屏掉帧或每页一张截图都不能替代这一步。

未开启motion且没有视频素材的旧报告可继续使用静态页导出。动态图像缓存按HTML/CSS/运行脚本、素材摘要、时间轴、渲染器及尺寸帧率区分。模板/素材改动会使对应缓存失效，配音缓存继续复用。

## 动态验收

除了联系表，至少检查同一页两个不同时刻的画面，确认卡片/图表存在中间态，短片实际运动，拖动和回退恢复正确状态。检查切换后素材和片尾停帧，不能只验证`video`元素存在。

`motion-qa.json`记录实际导出帧数、多个时间点的页面边界、视频定位时间和浏览器错误；`check`完整解码确认总帧数、音轨及字幕。记录源短片的帧变化和最终MP4截帧差异，不能把仅有解码器或音轨字段当成动态播放通过。手工/助理视觉检查及听取范围分别写明。
