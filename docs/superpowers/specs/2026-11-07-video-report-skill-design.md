# video-report skill：调研与设计方案

调研日期：2026-11-07。状态：设计已获用户“直接制作”指示，已完成实现及真实案例验证。

本文保留初始设计时点的方案，后文“第一版建议”“待定”“当前没有运行验收”等表述是设计阶段原文。实际实现、安装入口与已验证范围以 [README](../../../README.md)、[skill](../../../skills/video-report/SKILL.md) 和 [案例QA](../../../examples/format-acceptance/qa-summary.json) 为准。外部字幕入口目前为内联时间记录，持续动画、Azure及ASR等扩展仍未实现。

## 1. 要做成什么

把已有调研、总结、概述，转换成可以继续编辑的演示 HTML，以及带配音和字幕的 MP4。Skill 同时包含内容编排技巧、制作 SOP、环境安装与诊断、重复使用的脚本、可改的画面模板。

它接收已完成的材料，也能衔接当前对话已有的调研结果。没有材料时先完成必要调研并保存来源。不是每次制作视频都重新搜索，也不把未经核实的模型补充写成事实。

第一版默认中文、16:9、1920×1080、30 fps，目标为约 3～5 分钟的信息讲解。默认值可改；实际时长由合成音频决定。首先交付单个视频的完整生产流程，批量生成与复杂动画随后扩展。

## 2. 路线比较与推荐

| 路线 | 适合的工作 | 额外成本与限制 | 决策 |
| --- | --- | --- | --- |
| 自有 HTML/CSS + Playwright + FFmpeg | 类 PPT、图表、对比、流程、研究简报 | 需要维护时间轴和少量模板；任意网页动画不能直接保证可重现 | 第一版默认 |
| reveal.js + Playwright + FFmpeg | 已有 reveal.js 演示文稿，或需要演讲者模式、手动翻页 | 导出仍需解决声音、字幕、计时；自动翻页不能替代统一时间轴 | 保留接入方式，不作为硬依赖 |
| Remotion | 大量持续动画、精细帧控制、React 团队的批量视频产品 | 增加 React/Node 工程和渲染管理；商业使用需核对许可证适用条件 | 后续可选渲染器 |

推荐理由：用户的核心输入是研究内容，核心画面是演示页。第一版把内容质量、中文配音、字幕和稳定导出做通，采用可自由编辑的本地 HTML，避免为简单讲解引入整套动画工程。这个推荐是基于上述产品需求的工程判断，不是性能实测结论。

reveal.js 支持单页和片段的 `data-autoslide`，但用户交互默认可能暂停自动播放，因此录制不能仅依赖翻页计时。[官方自动播放说明](https://revealjs.com/auto-slide/)

Remotion 当前价格页区分符合条件的个人／小团队与公司许可，并区分手工创作、自动化产品。Skill 应链接许可说明，避免写死长期有效的免费承诺。[Remotion 许可证](https://www.remotion.dev/docs/license)、[当前价格与适用条件](https://www.remotion.dev/pricing)

## 3. 核心结构：用实际音频建立统一时间轴

制作链路：

> 材料与来源 → 叙事提纲 → 分镜与口播 → 分场景配音及边界事件 → 音频实测 → 统一时间轴 → HTML 页面状态 → 视频、字幕与质检

模型负责选择论点、组织故事、设计页面、修改文案；脚本负责测量、计算、导出和校验。不要让模型手算每页秒数，也不要让多个脚本各维护一份时长。

### 输入契约

`report.json` 保存画布、帧率、语言、配音配置，以及按顺序排列的场景。每场景有：

- 稳定的 `id`、页面类型、结论式标题、展示内容。
- 完整口播 `narration`，以及必要的术语读音或替换词；展示文本与发音文本分开。
- 来源 `source_ids`，对应 `sources.json` 中的出处、日期、相关论点及访问时间。
- 局部素材路径、显式停顿、可选的分步展示 cue。

来源信息不要求全部挤进画面；在相应页保留简短出处，完整资料随项目交付。推断、预测、示例数字需要明确标记。

### 音频与时间契约

- 每场景独立生成音频及原始边界事件。先解码到相同采样率的 PCM WAV，再拼接，最终只进行一次有损音频编码；避免直接连接不同 MP3 文件带来的格式、编码延迟问题。
- 场景时长来自解码后的样本数，加上明确设置的头尾停顿。供字幕使用的时间戳必须映射到该音频时间基准；抽听确认服务端边界与解码后声音一致。
- 时间轴保存全局起止时间、帧区间、音频样本区间和字幕区间。所有边界由累计时间一次换算；禁止把每段独立舍入后的时长持续相加。
- 画面与字幕导出都读取同一时间轴。场景本身不维护另一个自动播放计时器。
- 第一版以硬切、页内分步出现为主。可选的淡入淡出在已分配的场景时间内完成。跨场景重叠转场必须显式计入总时长，不能加上 `xfade` 后仍沿用原字幕偏移。
- 页面预览以主音频播放位置驱动画面。暂停、拖动进度条、跳页，都调用同一时间定位接口。

### HTML 导出契约

模板提供按场景及 cue 定位的确定性渲染接口。导出时等待字体、图片解码、图表布局完成，并检查页面错误、素材缺失和文字越界。

默认把每个静态页面状态截成图，按时间轴保持该画面，由 FFmpeg 编码。这样不用为静止的五分钟讲解截取九千张重复图片。页面有多个 cue 时，分别导出相应状态。

持续运动的场景才使用按绝对帧定位的渲染模式；后续可切换到 Remotion。不要把浏览器实际运行速度当成视频帧率，也不要声称任意外部网页都能直接接入。

Playwright 的视频录制默认会将视口缩放到 800×800 范围，且文件在 context 关闭后才保存。该功能适合测试录像；第一版成片采用明确画布尺寸的截图合成。[Playwright 视频说明](https://playwright.dev/docs/videos)

Playwright 的虚拟时钟可控制 JS 定时器及 `requestAnimationFrame`。它是测试或适配已有页面的工具，不等于所有 CSS 动画、媒体解码和音频都获得确定性控制。[Playwright 时钟说明](https://playwright.dev/docs/clock)

## 4. 配音与字幕选择

| 入口 | 第一版处理 | 使用边界 |
| --- | --- | --- |
| edge-tts | 默认低门槛试制方案，保存音频及词／句边界 | 第三方客户端调用在线服务；联网可用性需实测，不承诺 SLA 或长期免费 |
| Azure Speech | 接口预留，稳定生产需求时按配置接入 | 需要账户与密钥；SSML、词边界等能力依具体接口与音色验证 |
| 用户提供录音 + SRT | 校验时间、文本及媒体长度后复用 | 允许跳过在线配音；字幕质量仍需抽查 |
| 用户仅提供录音 | 后续可选 ASR／强制对齐流程 | 第一版不自动安装大型语音模型，不以字数比例冒充精确对齐 |

截至调研日，PyPI 上 edge-tts 当前版本为 **7.3.1**，包元数据声明 Python `>=3.7`；这不等于已在本机 Python 3.14 上安装验证。已直接检查该发布版本 wheel 中的源码和说明：

- `Communicate` 支持 `WordBoundary`、`SentenceBoundary`，默认是 `SentenceBoundary`；处理器同时支持两种事件。
- CLI 可同时输出音频与 SRT。程序接口适合保留原始事件，后续按中文阅读习惯重组字幕。
- 包说明明确不支持自定义 SSML；不能套用任意 `<break>`、多音色或风格标签教程。需要精确停顿时拆段合成并插入静音，或选用明确支持该能力的服务。
- 支持语速、音量、音高参数；音色在运行时查询，避免将某个名称视为永久可用。

来源：[PyPI 发布页及项目说明](https://pypi.org/project/edge-tts/7.3.1/)、[该版本元数据](https://pypi.org/pypi/edge-tts/7.3.1/json)。原始 GitHub 文件读取失败后，改为直接检查 PyPI 发布包；没有调用实际语音服务。

Azure 文档说明 `WordBoundary` 提供相对输出音频的 offset，以及输入文本的位置。事件产生速度可能快于播放速度，所以仍需要调用方做时间同步。[Azure 语音合成事件](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-speech-synthesis)

### 字幕 SOP

1. TTS 返回边界时，优先使用边界，不再把合成声音转写一次。保留原始事件以便重排字幕。
2. 优先按标点与意群拆分；中文以每行约 14～22 字、最多两行为起点，再按画布和实测阅读速度调整。这是排版建议，不是固定标准。
3. 词边界能够支持较细粒度的拆分；只有句边界时，先缩短配音输入的句子。若仍做句内插值，必须标记为估算，不能标成逐词精确对齐。
4. 字幕展示正确术语和数值，口播可使用便于听懂的读法；两者通过 cue 保持对应，不直接逐字符假定相等。
5. 输出 UTF-8 SRT 和用于烧录样式的 ASS。默认成片烧录字幕，同时保留 SRT 方便另行编辑；另存无字幕版本可由参数开启。
6. 检查非负时间、起止顺序、超出音频、意外重叠、过快阅读、长时间空白。字幕加上场景偏移和显式停顿后再生成全局版本。
7. 校对开头、中段、结尾和所有场景交界，关注专有名词、中英混读、年份、百分数、小数及单位。

## 5. 内容与画面制作 SOP

### A. 收束材料

优先从上下文推断受众、目的、语言、时长；缺少关键限制时再问。没有明确偏好时，采用中文 3～5 分钟简报，并在交付中说明默认值。

先写出一句主要结论，再选择三到五个支撑点。把已知事实、解释、建议区分清楚。来源过时或互相矛盾时，先核对材料，不能靠画面掩盖内容问题。

### B. 从报告改成口播

- 开场直接给结论或问题，尽快告诉观众看完能知道什么。
- 每页承担一个信息任务：提出问题、解释机制、展示证据、比较方案、给出建议。
- 页面标题尽量表达结论；正文放证据，旁白解释“为什么”。避免把报告段落原封不动铺满画面。
- 口播用短句，说明数字的含义、单位和比较基准。实际试读后再估计语速，最终以配音测量为准。
- 时间超标时先删枝节、压缩文案；不要自动把配音加速到难以理解。

### C. 先做分镜，再生成画面

分镜表逐页列出标题、主视觉、屏幕文字、口播、来源、进入与离开条件。第一版模板覆盖封面／结论、关键指标、对比、流程、时间线、图表、结尾建议与来源页。

优先用 HTML/CSS 和 SVG 表达数字、标签、流程和图表；需要照片或插画时再选择真实素材或生成图像。不要用生成图里的文字承担关键事实。

在 1080p 画布上，标题约 48～72 px、正文约 28～40 px 作为起点；给字幕预留底部空间，重要内容离画面边缘至少约 5%。这些是模板起点，必须经真实尺寸及缩小预览检查。

图表标清单位、时间、基线和来源。同类信息保持同一颜色含义。少量分步出现服务于讲解，不给每个元素添加独立动画。

### D. 先验证短样片

先做约 30～60 秒的多场景样片，检查音色、术语、密度、字体、字幕位置及导出链路。只有内容或画风需要确认时才设置人工评审；普通生成任务在已有授权范围内继续完成，不把每页批准变成通用前置条件。

### E. 合成与交付

视频默认采用 H.264、AAC、`yuv420p` 和便于网络播放的封装配置，保持固定帧率。底噪、响度或音乐需求出现时再处理；默认不添加背景音乐。

音频响度按选定目标检测／归一化，并检查真峰值。不能对已经归一化的音轨反复无条件处理。具体参数与支持的 FFmpeg 滤镜随实际安装版本确认。

交付 MP4、可编辑 HTML、字幕、配音、分镜、来源和制作记录。只有任务要求时才上传或发布成片。

## 6. Skill 与脚本布局

建议仓库内保存可发布的 skill 源码，并在实现验收后安装到个人技能目录。第一版使用 Python 统一调度，无需 Node 运行时；选择 Remotion 扩展时才引入 Node。

拟议目录：

```text
skills/video-report/
  SKILL.md
  agents/openai.yaml
  references/
    workflow.md
    visual-design.md
    timing-and-captions.md
    environment-and-troubleshooting.md
  scripts/
    bootstrap.py
    doctor.py
    video_report.py
    requirements.lock
  assets/
    deck-template.html
    theme.css
    demo-report.json
```

- `SKILL.md`：精简入口，包含触发场景、基本制作顺序、输出约定和按需阅读的引用；不塞入整篇调研报告。
- `workflow.md`：分镜与口播 SOP，包含来源与事实检查、制作中断后的恢复方式。
- `visual-design.md`：页面密度、字号、安全区、图表、分步展示和样片检查技巧。
- `timing-and-captions.md`：输入数据约定、时间单位、字幕重组、音频 padding 与转场偏移。
- `environment-and-troubleshooting.md`：Windows 优先的安装、跨平台差异、常见报错及诊断动作。
- `bootstrap.py`：建立独立 venv，安装锁定的 Python 依赖和对应 Chromium。FFmpeg 的系统安装另有显式选项或平台说明，不修改全局 Python。
- `doctor.py`：检查依赖、Chromium、FFmpeg/ffprobe、必需编码器与滤镜、实际可渲染的中文字体，以及输出目录。
- `video_report.py`：提供可分阶段执行的 `init`、`validate`、`tts`、`render`、`build`、`check`。`build` 调用同一组阶段函数，失败后可恢复。
- `assets`：一套可修改的模板和一个真实可运行的小例子；不堆积暂时用不到的主题和占位脚本。

脚本变长时按媒体、配音、字幕、渲染职责拆模块；不为目录结构提前制造多层框架。

### 环境与安装

本机观察：Windows PowerShell，Python 3.14.3，Node 24.13.0；通过 `Get-Command` 未发现 PATH 中的 FFmpeg、ffprobe 或 uv。这里只能判断 PATH 可见性，不能据此断言机器其他目录没有安装。

最小运行依赖为 Python、Playwright Python 包及 Chromium、FFmpeg 和 ffprobe。默认配音另需 edge-tts；如用 Pillow 做联系表则一并纳入锁定依赖。Azure SDK、大型 ASR、GPU 环境、Remotion 都是可选项。

实现阶段先验证本机 Python 3.14 的轮子与浏览器兼容性；若实际失败，提供独立的 Python 3.12／3.13 环境路径，不替换系统 Python。锁文件来自实际通过的环境，不能把“元数据允许”当成兼容性证明。

Windows 安装说明需覆盖：虚拟环境的解释器直调、路径带空格和中文、UTF-8 文件与终端、FFmpeg 字幕滤镜的路径转义、中文字体 fallback、浏览器缓存目录。脚本用参数数组启动子进程，不依赖拼接 shell 命令。

FFmpeg 安装后检测 H.264、AAC、`subtitles`／libass 及音频处理所需滤镜；不能只判断 `ffmpeg -version` 存在。官方分发说明与滤镜资料需要在实现时结合实际构建核对。[下载页](https://ffmpeg.org/download.html)、[滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)、[上游滤镜源码文档](https://github.com/FFmpeg/FFmpeg/blob/master/doc/filters.texi)

已通过 FFmpeg 上游源码文档核对：`subtitles` 需要构建时启用 libass；`concat` 滤镜要求各段从时间戳零开始；`xfade` 输入需要一致的恒定帧率、分辨率、像素格式和时间基准。自动换行还受 libass 的版本及构建能力影响，中文字幕应显式排版，不能只靠系统自动折行。字幕字体、模板图片若随项目打包，应保留各自来源和许可证。

### 复用与失败恢复

- 配音缓存键包含正文、音色、服务、语速及相关配置；图片缓存键包含画面内容、模板、字体、尺寸和素材。
- 修改颜色或布局只重建画面；修改口播重建相应配音、时间轴及依赖产物；改变字幕样式重建字幕烧录和成片。
- 网络调用设置超时和有上限的重试；配音失败保留已成功场景，返回明确错误。不能用静音替代失败配音后宣称成功。
- 缺字体、图片失败、页面越界、媒体长度不符时，在编码前给出对应场景及文件。
- 保存输入摘要、依赖版本、配音设置、各阶段状态与产物路径，避免续跑时误用旧缓存。API 密钥从环境读取，不写进 HTML、日志或交付目录。

## 7. 第一版产物与验收

一次任务的交付目录包含：

| 产物 | 用途 |
| --- | --- |
| `video.mp4` | 带配音和字幕的成片 |
| `deck/index.html` 及本地素材 | 可编辑、可播放预览的演示页 |
| `subtitles.srt`、`subtitles.ass` | 可编辑字幕与烧录样式 |
| `voice.wav` | 可复用的合并旁白 |
| `report.json`、`storyboard.md`、`sources.json` | 内容、分镜与来源 |
| `timeline.json`、`manifest.json` | 可重现构建所需时间轴及记录 |
| `poster.png`、`contact-sheet.png` | 封面及全片画面快速检查 |
| `qa.json` | 自动检查结果及仍需人工确认的问题 |

验收样例采用约 45～60 秒、四页的中文讲解，包含中英混排、年份、百分比、长句、图表及跨页字幕偏移。

必须实际验证：

1. 干净环境安装、环境诊断、完整构建成功；记录用到的真实版本与运行命令。
2. MP4 可解码，尺寸、帧率、编码及音轨符合配置；内部时间轴边界量化误差不累计，最终封装的长度差异有明确容差并检查。
3. 字幕顺序正确、不超出片长，起中末与跨页处抽听对齐；有声音，没有因失败被替换成静音。
4. 页面无缺图、方框字、越界、控制台错误；逐页联系表和至少一轮视频播放检查通过。
5. 在带中文和空格的 Windows 工作目录中完成构建；确认 ASS 的字体与路径可用。
6. 中断后续跑，修改某页口播后仅重新生成受影响部分，时间轴与缓存都正确更新。
7. 对缺失素材、超长字幕、配音网络失败做有意义的失败测试；不为纯样式修改堆积实现镜像测试。
8. 用另一份未见过的材料验证 skill 能指导新任务；明确哪些能力已经实测，哪些仍只在文档中说明。

当前没有运行上述视频验收；这些是实现完成的判定条件。

## 8. 研究结论与待定范围

第一版建议只承诺：**已有材料／当前调研 → 分镜和口播 → 受控 HTML 演示 → 配音时间轴 → 字幕 → MP4 → 自动检查和人工抽查**。

已有录音加 SRT 可作为无在线配音入口。已有任意 HTML 的自动适配、只有录音时的强制对齐、持续复杂动画、批量生产、配乐自动混音、PPTX 导入导出，都留到实际需求出现后扩展。

需要确认的核心设计选择只有一个：是否先按上述轻量路线实现完整闭环。默认值不构成永久限制，模板、配音适配器及渲染器均可替换。

资料核对说明：网页检索工具本轮不可用，已直接读取 Playwright、reveal.js、Remotion、Azure 官方站点及 PyPI 发布材料。FFmpeg 官方站点读取超时，已改从官方 GitHub 仓库的源码文档核对滤镜限制；具体构建能力仍需在实现时实测。本文没有给出未经实测的速度、音质或成本保证。
